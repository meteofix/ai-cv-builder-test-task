# Web app — screens, client, editor

**Area:** `apps/web/src/**`, `apps/web/public/**`, `apps/web/index.html`. Build and container files (`package.json`, `vite.config.ts`, `tsconfig*.json`, `Dockerfile`, `nginx.conf`) are the user's. **Builds on (frozen at S0):** `ROUTES`, the DTOs, `problemSchema`, `cvDocumentSchema`, `answerSchema`, `LIMITS` from `@cv/shared`; `renderCvShell` and `renderCvBody` from `@cv/cv-template`. Decisions: [001](../DECISIONS.md#001-react-spa-behind-nginx-on-one-origin), [004](../DECISIONS.md#004-polling-while-a-job-is-active), [011](../DECISIONS.md#011-one-cv-document-with-optimistic-locking-read-only-editor-during-ai-jobs), [012](../DECISIONS.md#012-single-flight-autosave), [013](../DECISIONS.md#013-staged-draft-assembled-on-read), [019](../DECISIONS.md#019-one-html-template-for-preview-and-pdf).

## Goal

The whole flow — sign up, create a CV from a PDF or text, watch it being written, answer questions, edit, download the PDF — works on a desktop and on a 360 px phone, never loses typing, and always says what went wrong.

## Contracts

- **Routes of the app:** `/login`, `/signup`, `/` (list), `/cvs/new`, `/cvs/:id` (progress, failure, editor). Anything else → the list. Without a session (`GET /api/auth/me` is 401) every route except login and sign-up goes to `/login` and comes back after login.
- **API client:** one typed client over `ROUTES` (method, path, body and response schemas); `fetch` with `credentials: 'same-origin'`, JSON bodies, multipart for `createCvFromPdf`. Responses are parsed with the route's response schema. Errors become one `ApiError` type: `problem+json` → its `code`, `detail`, `requestId`; a non-JSON error from nginx (413, 502, 504) → a code by status (`PAYLOAD_TOO_LARGE`, `UNAVAILABLE`); a network failure → `OFFLINE`.
- **Mock API:** MSW handlers in `src/test/` (and for `pnpm dev` without the API, optional) that follow the same schemas; tests parse handler responses with the response schema so the mock cannot drift.

## Behaviour

1. **Auth screens.** Email and password with the limits of `credentialsSchema`; `INVALID_CREDENTIALS` → "Wrong email or password."; `EMAIL_TAKEN` → "An account with this email already exists."; `RATE_LIMITED` → "Too many attempts. Wait a minute and try again." Logout in the header.
2. **List** (`/`): a card per CV with role, name (or "Untitled" when `fullName` is null), state ("Generating…", "Failed", "Updating…", "Ready") and "N open questions"; "New CV" button; delete through a `<dialog>` confirmation. The list is polled every 1.5 s only while some item is `generating` or `updating`.
3. **New CV** (`/cvs/new`): tabs "Upload PDF" / "Paste text" and the target role (required). Before upload the file is checked: not a PDF (by type or `.pdf` name) or larger than `LIMITS.maxPdfBytes` → an inline message, no request. Server codes map to messages: `PDF_NO_TEXT` "This PDF has no text layer (it looks scanned). Paste the text instead.", `PDF_ENCRYPTED`, `PDF_TOO_MANY_PAGES` (10 pages), `PDF_INVALID`, `PDF_TOO_LARGE`, `GENERATION_LIMIT_REACHED` (the server's `detail`). On 202 → `/cvs/:id`.
4. **Progress** (`/cvs/:id` without a document): `GET /job` every 1.5 s while the job is active; a stepper with the three steps (Writing · Checking facts · Finishing) from `job.step` (`write`, `judge`, `finalize`; a job stored before v2 at `extract` shows the first step). There is no draft: the author writes the whole CV in one step (decision 035). When the job succeeds → fetch the CV and show the editor; polling stops. A reload at any point shows the same state (everything comes from the server).
5. **Failure:** a failed job shows its `error.message` and a Retry button (`POST /job/retry`; 409/429 messages from the code); the stepper marks the step that failed.
6. **Editor** — one page: desktop: the form on the left, the preview on the right; phone: experience and education cards collapse (`<details>`), a sticky section bar with question counters, the preview opens in a `<dialog>`. One react-hook-form form for the whole document with `zodResolver(cvDocumentSchema)`. Fields: contacts, headline, summary, positions (↑/↓ buttons to reorder, subsections of bullets), education, skills, additional sections (entries with groups of lines); dates as two `<select>` (month with "—", year) plus, for positions only, a "Present" checkbox that clears the end date — education has no "Present" (the document schema stores only `start` and `end` for it). A "CV language: English/Ukrainian" label. On a phone (below `lg`) the header is not sticky, a sticky section bar (Contacts, Summary, Experience, Education, Skills, More) shows the number of open questions per section, and a sticky action bar holds the save status, "Preview" and "Download PDF"; there is no preview column. No rich text, no "improve with AI". Look and states follow `docs/design/app/` (its README says what is ported).
   - **Links:** when a link field loses focus and its value has no scheme, `https://` is prepended (the same rule as the server's draft). A value that still fails `linkSchema` — like any other field that fails `cvDocumentSchema` — shows its error under the field, and autosave pauses with the status "Not saved — fix the highlighted field" until it is fixed: the `PUT` always carries the whole document, so a partial save is not possible without a second code path (chosen as the simpler option).
   - **Empty rows are not part of the CV.** A link, bullet, line, skill, group or card that was just added and has no text, and an optional field left empty, are left out of what is saved and previewed; they stay in the form so the person can fill them. A group with no item left is dropped, a blank group title is `null`, an entry with no title, no dates and no line is dropped, and so is an additional section with neither a title nor an entry. Adding an empty row is therefore not an edit and sends nothing.
   - **Item groups** (decision 036): every list of the document is made of groups `{id, title | null, items}`, and the editor shows them with one component (`ItemGroup`): the group's title field, its items, and "Remove <group>". A group without a title is a plain list. Item ids are new UUIDs, unique across the groups of a list; an item keeps its id when its row moves.
     - _Bullets of a position:_ its groups are subsections. An untitled group shows no title field, only "Add a subsection title" (which opens the field and focuses it; the field stays while it is cleared, and an empty title is saved as none). Each bullet row has "Move bullet N up/down" and "Remove bullet" (at once); "Add bullet" adds to its group, at most `LIMITS.maxBulletsPerPosition` bullets across the groups. "Add subsection" adds a group with its title field open and one empty bullet (at most `LIMITS.maxGroupsPerList`). "Remove subsection N" is offered unless the group is the only one and has no title; a group that still has text asks "Remove this subsection?" first, an empty one goes at once. A position without groups shows "Add bullet", which creates an untitled group. A new position starts with one empty untitled group.
     - _Entries of an additional section:_ a section has a title and entries; an entry (a project, a course, a certificate) has an optional "Entry N title", "Start" and "End" (month and year, no "Present") and its groups of lines, edited like bullets ("Line N", "Add line", "Add subsection"; at most `LIMITS.maxLinesPerEntry` lines across the groups). Entries have "Move entry up/down"; "Remove entry" asks "Remove this entry?" first. "Add entry" (at most `LIMITS.maxAdditionalItems`) and "Add section" start with one empty untitled group. An entry with neither title nor dates is a plain list of lines ("Languages").
     - _Skills:_ see below; each group is an `ItemGroup` whose items are one comma-separated line.
     - On a phone (≤ 640 px) the ↑/↓/remove buttons of a row sit under its field, so the field keeps the width of the card.
   - **Summary:** a textarea (line breaks between paragraphs are kept as typed and saved). Under it a counter "N characters · 400–600 is advised"; above 600 characters it turns into a warning, "N characters — longer than the advised 400–600". Advice only: nothing is blocked or cut (the hard cap stays `LIMITS.maxSummaryChars`).
   - **Page count** (owner's decision): next to the preview (in its head on a desktop, at the top of the preview dialog on a phone, once it has been opened) the editor shows the estimated number of PDF pages: "1 page", "2 pages", and from 3 pages on a warning "N pages — recruiters usually advise up to 2". It is measured from the preview: the height of the template's `.cv` sheet less its 17 mm padding, divided by the printable height of an A4 page with the 17 mm `@page` margin of the template ((297 − 2 × 17) mm at 96 px per inch ≈ 994 px), rounded up (2 px of tolerance for rounding). Page breaks the template avoids inside an item can add a little, so it is an estimate; it never blocks the PDF or anything else.
   - **Skills** come in groups (decisions 035, 036): per group a "Group N title" field (optional, always shown; empty is no title) and a "Group N skills, separated by commas" field that keeps what the person types and turns it into skills on every change (a skill whose name stays keeps its id; the line is cut like a kept skill line, grounding.md §4, and shows the skills joined with `, `, or with `·` when a name has a comma of its own, so it reads back as the same skills); "Add group" and "Remove group". A group with no skill left is not saved.
   - **The order of the experience:** when `GET /not-in-cv` gives an `orderReason`, a note above the experience says "Order of your experience: <reason>"; ↑/↓ reorder as before.
   - **Removing:** "Remove" on a position, an education entry or an additional section opens a `<dialog>` confirmation ("Remove this position?" / "Remove this education entry?" / "Remove this section?", buttons "Remove" and "Cancel"), like deleting a CV: each of them can hold several lines. Autosave runs only after "Remove". An entry of an additional section, and a subsection that still has text, ask the same way ("Remove this entry?", "Remove this subsection?"). Bullets, skills, skill groups, links, empty subsections and single lines are removed at once.
7. **Autosave** — single-flight. "Is there anything to save" is a comparison of the form (as it would be saved) with the last state the server confirmed, not a counter: undoing an edit saves nothing and a reload from the server is never an edit. Changes are debounced 1 s; at most one `PUT` is in flight; changes made meanwhile are sent next with the version returned by the previous save; after success the form is not reset (only the stored version and snapshot change). Status: "Saving…", "Saved", "Save failed" (retried with backoff 1 s, 2 s, 5 s). `VERSION_CONFLICT` → load the latest CV, reset the form, show "This CV was changed elsewhere. We loaded the latest version." `JOB_ACTIVE` → read-only. Pending changes are flushed before answering a question, before logging out and before leaving the editor: a navigation (a link, Back) with unsaved changes is held until the save finishes, and when it cannot be saved a dialog asks "Leave without saving?" ("Log out without saving?" for the logout); if the save ends in a conflict the person stays on the page, where the notice is, and after the session has ended nobody is asked. `beforeunload` warns while changes are unsaved.
8. **Read-only during AI jobs:** while the latest job is active the form is disabled, the card of `job.target` shows "Updating…" (a target that is a group, `p1-g2` or `a1-e1-g1`, marks the card of its job or entry), and `GET /job` is polled; when the job ends the CV is fetched and the form reset from it.
9. **Questions:** a "Needs clarification · N" block lists open questions with their `prompt` and `context`; a dates answer uses the same month/year/Present inputs, a text answer a textarea (≤ `LIMITS.maxAnswerChars`); "Show in CV" scrolls to and highlights the target: a job, an entry or one of their subsections (each has an element `item-<id>`), or the job or entry when that subsection no longer exists, else the section. Answering flushes autosave, then `POST .../answer` → the card shows "Updating…". "Dismiss" → `POST .../dismiss`. Answered questions show "Applied", "Partially applied" with `applyNote`, or "Could not apply" with `applyNote` and the answer form again (the API accepts a new answer to a failed application). When the document has no email or no phone, computed items "Add email" / "Add phone" focus the field (no API call). An `applied` answer may carry a note too (the earlier wording of its part went to "Not in your CV"); the card shows `applyNote` for every status.
10. **Not in your CV:** a panel from `GET /not-in-cv` grouped by reason: "Left out" (`not_included`, with the author's reason as `context`), "Not placed anywhere" (`not_placed`), "Ignored (looked like an instruction)" (`ignored`), each with `text` and `context`. Every item except an ignored one has "Add": it puts the text back word for word where it belongs, and anything without a place (or with no room left within the document's limits) into an extra section "Additional information" / "Додаткова інформація"; the change is saved like any edit. Where it goes, by `section` and `itemId`:

- `experience` + a position: a bullet at the end of the position's **last untitled group**, or of a new untitled group at the end when every group has a title (a group title is a claim checked for its own items) (a company block that shares its bullets: its first position);
- `summary`: a sentence after the summary;
- `skills` + a skill group: its names added to that group, without a name the group already has; without a known group, a new untitled group;
- `additional` + an entry: a line at the end of the entry's last untitled group (or a new untitled group at the end); `additional` + a section: a line of the section's last entry when that entry is a plain list (no title, no dates), otherwise a new untitled entry with that one line. The fallback section takes lines by the same rule, so lines added one by one stay one list.
  The CV already shows a text when it equals a bullet, a line, the title of an extra entry, the summary or one of its sentences, or when every name of it is among the skills. An item whose text the CV already shows is not listed. When the answer says `sourceCoverage.low`, the editor shows above the questions "Part of your CV could not be read. Check Not in your CV, or paste the text of your CV instead."; the link opens the panel and scrolls to it (owner's decision R0-SIGNAL, ADR 034).

11. **Preview:** an `<iframe sandbox="allow-same-origin">` (no `allow-scripts`); its document is set once with `renderCvShell({ fonts: { baseUrl: '/fonts' } }, locale, title)`, then every change writes `renderCvBody(document)` into its `body` — no reload, no flicker, scroll kept. Height follows the content (rounded up, so the frame never scrolls by a fraction of a pixel); the page is scaled from 794 px to the available width. On a desktop the preview column stays in the viewport (`position: sticky`, at most the window's height under the header) and scrolls on its own, so the end of a long CV is visible without scrolling the form; the scroller is a focusable region ("CV preview") for the keyboard, outlined by the global focus style. Layout is not covered by the jsdom tests (no layout engine); checked in a real browser.
12. **PDF:** a "Download PDF" button fetches `GET /api/cvs/:id/pdf`; on 200 the blob is saved through an object URL with the file name from `Content-Disposition`; an error response is a problem+json that shows a message (`DOCUMENT_NOT_READY`, `PDF_RENDER_FAILED`). Disabled while a save is not finished (pending, failed or waiting for a field to be fixed) or a job is active: the file must be the document the person sees. A PDF error is shown as a sentence next to the button (above the buttons on a phone).
13. **Errors and connection:** any 5xx shows "Something went wrong. Error ID: <requestId>"; a banner while the browser is offline or the API is unreachable; a session that expires mid-use → `/login`, to which the person returns after signing in again (a logout they asked for returns nowhere); a failed refresh of the user while the API is down does not end the session. A request that failed is asked again with growing pauses (to 15 s, at most 20 times, never for a 4xx).
14. **Layout:** no horizontal scroll at 360 px on every screen; everything works with the keyboard; English UI without i18n.

## Acceptance examples

Tests in `apps/web/src/**/*.test.tsx` with Testing Library and MSW; names start with the example id; fake timers where time matters.

- **WEB-1 — sign-in gate.** With `GET /api/auth/me` answering 401, opening `/cvs/new` shows the login page; after a successful login the app is on `/cvs/new`.
- **WEB-2 — login error.** Login answered with 401 `INVALID_CREDENTIALS` → "Wrong email or password." and the password field keeps focus.
- **WEB-3 — the list polls only while needed.** A list with one `generating` item → `GET /api/cvs` repeats every 1.5 s; once the handler returns it as `ready`, no further list requests happen within 5 s.
- **WEB-4 — files are checked before upload.** Choosing an 11 MiB PDF, or a `.png`, shows a message and sends no request.
- **WEB-5 — progress.** Job answers in sequence `queued`/`null`, `running`/`write`, `running`/`judge`, `succeeded`/`finalize`: the stepper (three steps) follows and shows no preview; after `succeeded` the editor shows the document and job polling stops.
- **WEB-6 — failure and retry.** A failed job with `error: {code: "AI_UNAVAILABLE", message: "…"}` shows the message and Retry; Retry sends `POST /job/retry` and returns to the progress view.
- **WEB-7 — typing during a save is neither lost nor a conflict.** In the editor at `version: 3`: type "A" in the headline → after 1 s one `PUT` with `version: 3` is sent and held open by the handler; type "B" meanwhile → no second `PUT` yet; release the first (answers `version: 4`) → exactly one more `PUT` with `version: 4` and a headline ending in "AB"; the input shows "AB" throughout; no 409 happens.
- **WEB-8 — a conflict reloads the latest version.** A `PUT` answered with 409 `VERSION_CONFLICT` → the CV is fetched again, the form shows the server's document, and the conflict message is visible.
- **WEB-9 — read-only while AI updates a card.** A CV whose job is `running` with `target.itemId` of the second position → every input is disabled and that card shows "Updating…"; when the job turns `succeeded` the CV is fetched and the inputs are enabled.
- **WEB-10 — answering a dates question.** An open `dates` question: choose month "Mar", year 2021 and "Present" → `POST .../answer` with `{"answer":{"type":"dates","start":"2021-03","end":null,"current":true}}`; a pending autosave is sent before it; choosing month "—" sends `"2021"`.
- **WEB-11 — not in your CV.** Items of the three reasons are shown under their group titles, a `not_included` item with its reason.
- **WEB-12 — preview without reloads.** After several edits the iframe's document was set once, its `body` holds the latest name, and the iframe has `sandbox="allow-same-origin"` without `allow-scripts`.
- **WEB-13 — error messages.** A 500 `problem+json` with `requestId: "req-42"` → "Error ID: req-42"; a 413 with an HTML body → "The file is too large (max 10 MB)."; a 502 with an HTML body → the API-unreachable message.
- **WEB-14 — reorder.** ↑ on the second position moves it first and autosaves the new order; ↑ is disabled on the first position.
- **WEB-15 — a link without a scheme.** Type `linkedin.com/in/iryna` into a link field and leave it → the field shows `https://linkedin.com/in/iryna`, and the next autosave `PUT` contains exactly that value. A value that is still invalid (`https://`) shows an error under the field and no `PUT` is sent while it stays.
- **WEB-16 — removing a position or a section asks first.** "Remove" on a position opens the dialog; "Cancel" → the position is still there and no `PUT` is sent; "Remove" again and confirm → the position is gone and exactly one `PUT` is sent without it. The same for "Remove section" on an additional section: "Cancel" keeps the section and sends nothing, confirming removes it with one `PUT`; removing a single line of a section needs no confirmation.
- **WEB-17 — skill groups.** The editor shows a group's title and its skills as one comma-separated line; after "Add group", typing the title `Cloud` and `AWS, GCP, ` keeps the trailing comma in the field and saves a group `{title: "Cloud", items: [AWS, GCP]}`; the existing skills keep their ids.
- **WEB-18 — "Add" from the panel.** A `not_included` item for position `pos-1` and a `not_placed` item without a place: "Add" on both puts the first as the last bullet of `pos-1` and the second into "Additional information"; both leave the panel; the saved document has them; an `ignored` item has no "Add".
- **WEB-19 — the order note.** `orderReason` in `GET /not-in-cv` shows as "Order of your experience: <reason>" in the editor.

## Definition of done

The acceptance examples pass; every screen is checked in a real browser at 360 px (no horizontal scroll) and on a desktop width, against the API on S1; `pnpm check` is green; this spec matches the code.

## Required tests

The acceptance examples, plus: `beforeunload` is prevented while changes are unsaved; a session that expires (a 401 from any request) leads to `/login`.
