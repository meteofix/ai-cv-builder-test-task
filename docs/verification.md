# How the requirements and the failure cases are verified

Test ids (AUTH-1, GEN-3, …) are the acceptance examples of [`specs/`](specs/). Paths: `api/test/` = `apps/api/test/`, `api/src/` = `apps/api/src/`, `web/` = `apps/web/src/`, `tpl/` = `packages/cv-template/test/`. The tests were mapped to the requirements by reading their bodies, not their names. The quality of the model's wording, ordering and summary is not covered by a test: it is measured by the [evals](evals.md).

## Failures and untrusted input

| Situation                                            | What happens                                                                                                                                                                                                                 | Tests                                            |
| ---------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------ |
| Page reloaded during a generation                    | The same step; the job goes on.                                                                                                                                                                                              | web progress tests                               |
| API killed during a generation                       | After the 30 s lease another worker resumes at the first unfinished step; steps whose result was committed are not repeated, a call interrupted before its result was stored can be. A killed worker uses one of 3 attempts. | job engine tests (lease, fencing, resume)        |
| Anthropic 429 / 500 / 502 / 503 / 504 / 529, timeout | Retried in the LLM client (`Retry-After` honoured, capped at 30 s), then the job is re-queued after 10 s and 30 s (3 attempts), then fails with a message and a Retry button.                                                | LLM client and generation tests                  |
| Invalid model output, call budget, refusal, bad key  | Re-asked with the validation error once per call; at most 15 model calls per run (every HTTP attempt counts; a manual Retry starts a new run); a refusal or a 401 is not retried.                                            | LLM client and generation tests                  |
| Empty file, or not a PDF                             | 422; the UI shows "This file is not a valid PDF."                                                                                                                                                                            | sources tests                                    |
| Scanned PDF, encrypted PDF                           | 422; the UI asks to paste the text or remove the password.                                                                                                                                                                   | an image-only PDF printed by Chromium, a fixture |
| PDF over 10 MB                                       | Refused in the browser; the API answers 413 `PDF_TOO_LARGE`, nginx 413 above 11 MB. Parsing runs in a worker thread with a time and heap limit, at most 10 pages.                                                            | sources tests                                    |
| Same CV edited in two tabs                           | The stale tab's save gets 409; its form is replaced by the latest version and says so.                                                                                                                                       | cvs and web autosave tests                       |
| Edit while an AI job changes the CV                  | The editor is read-only with "Updating…"; a save would get 409 `JOB_ACTIVE`.                                                                                                                                                 | cvs and web tests                                |
| Network lost in the browser                          | A connection banner; autosave keeps the typing and retries with backoff, then waits for the next edit.                                                                                                                       | web tests (MSW)                                  |
| A render error in the editor                         | A plain message and a Reload button instead of an empty screen.                                                                                                                                                              | web error boundary test                          |
| PDF rendering fails                                  | 503 `PDF_RENDER_FAILED`, a message next to the button.                                                                                                                                                                       | PDF endpoint tests                               |
| Generation limit                                     | 30 per user and 300 in total per rolling 24 hours (env); 429 with a message. It counts starts, not spend: a generation, a text answer and the retry of either each take one unit; a dates answer takes none.                 | generation queue tests                           |
| Password guessing                                    | Rate limit on login and sign-up; an unknown email gets the same 401, and the password hash is verified in both cases (timing is not measured).                                                                               | auth tests                                       |
| Prompt injection in the CV text                      | Lines that match the instruction patterns are cut before any model sees them and listed as ignored. Anything else reaches the models as data inside `<cv_source>`; the schema and the reviewer are the other layers.         | GEN-4, GRD-21, `grounding/instructions.test.ts`  |
| Someone else's CV id in the URL                      | 404 "This CV does not exist."; no route reveals or changes it.                                                                                                                                                               | the ownership table test                         |
| CV deleted during its generation                     | The cascade deletes the job; the worker's next fenced write matches nothing and it stops.                                                                                                                                    | job engine tests                                 |
| An answer that cannot be applied                     | The question shows "Could not apply" or "Partially applied" with a reason and can be answered again.                                                                                                                         | answer tests                                     |
| Database down                                        | `/api/health/ready` fails; the worker loop logs, backs off (1 s, 5 s, 30 s) and recovers (simulated failures of the loop).                                                                                                   | worker tests                                     |
| Plain-HTTP origin (a phone on the LAN)               | `crypto.randomUUID` is missing there; ids come from `crypto.getRandomValues`.                                                                                                                                                | web id tests                                     |

The same cases were also run by hand against the compose stack with the real API, on the pipeline before v2 (reload and `docker compose kill api` during a generation, a foreign id, empty / not-PDF / scanned / encrypted / oversized PDFs, two tabs, the injection samples). The v2 flow was re-checked end to end in a real browser at 360 and 1280 px (sign-up, PDF and text, steps, a question and its answer, "Not in your CV" → "Add", a manual edit, the PDF).

## Review and audit passes

Every commit went through the `reviewer` agent (BLOCKING / SHOULD-FIX / NITS, each finding answered), and the large pieces through Codex and mutation checks. Counts are from the saved reports.

- **auth:** mutation check 10 mutations, 9 caught, a test added for the survivor; Codex 1 P1 and 3 P2, all fixed.
- **pipeline:** mutation check 8/8; Codex regular review 3 P2 and adversarial review 3 BLOCKING, all fixed. The follow-up fixes were reviewed by Opus (Codex was unavailable): 2 BLOCKING (a partial contact value passed provenance; an invented `current` reached the CV unchecked) and 5 SHOULD-FIX, fixed in 4 rounds.
- **web:** mutation check 8/8; Codex 2 P1 and 5 P2 fixed; reviewer 1 BLOCKING (a logout race) fixed.
- **v2 (author + reviewer):** reviewer rounds 2/6/7, 1/4/4 and 0/6/8 (BLOCKING / SHOULD-FIX / NITS) on the final slice, all fixed or answered; Codex review 2 P2; Codex adversarial 2 P1 (headings that hold content; an answer that silently shortens an earlier item) and 1 P2 (link case), all fixed after the owner's decisions.
- **Reviewer test and holdouts:** 76 of 76 planted inventions flagged, 4 false alarms over 131 clean items; two holdouts found one and four defects, all fixed ([evals](evals.md)).
- **Final audit of `main`** (read-only, three audits): code cleanliness (2 BLOCKING / 20 SHOULD-FIX / 19 NIT), failures and untrusted input (1 / 25 / 29) and the honesty of this README (5 / 22 / 1). Fixed: stale screenshots, the unfinished sections of the README, the plain-HTTP id crash with an error boundary, the instruction filter edges (invisible characters, multi-line answers), the overstated README claims, leftover v1 code and wording, the ignore files, the environment documentation. Deferred, with reasons, in the README ("What I simplified and what is next"): silent cuts of long direct answers and of questions past the cap, a per-route throttle for retry and answer, web request timeouts and polling give-up paths, recycling a wedged Chromium, and renames of `factIds` and the `facts` column.
- **Low-depth security scan (Claude Security, whole repository, `main` before the audit fixes):** 0 findings. This is a triage scan, not a security audit. Not covered: dependencies, and runtime checks of auth, CSRF and upload limits (the project's own ownership-table and end-to-end tests are the evidence for those). `pnpm audit --prod` on the lockfile reports no known vulnerabilities.
